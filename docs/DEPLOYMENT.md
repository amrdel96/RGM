# Deployment preparation
Target: Vercel web application, Supabase PostgreSQL/Auth, Cloudinary media, existing Hostinger mail. Local/staging/production use separate databases, buckets and secret sets. Production credentials are CONFIGURATION REQUIRED. No deployment has occurred.
Before staging: dependency lock, clean build, reviewed migrations, Auth redirect URLs, RLS/roles, protected worker schedule, uploads, mock email/WhatsApp. Before production: backup/restore rehearsal, migration reconciliation, role tests, actual provider sandbox checks, reviewed contacts/legal/privacy configuration, monitoring and rollback.
DNS: obtain provider-generated website A/CNAME values only at cutover. Preserve existing Hostinger MX and email records. Review current SPF before merging sender mechanisms; never create multiple conflicting SPF records. Use provider-issued DKIM selectors; review DMARC reporting/enforcement with mailbox owner. No guessed DNS values.
Cutover: backup old site and database, freeze/import delta, verify migration counts/assets, apply tested redirects, switch website DNS, smoke test EN/AR inquiry persistence/delivery with controlled recipients, monitor errors. Keep old site backup available. Roll back deployment/DNS if critical journeys fail; database changes must be backward compatible, never destructive rollback that loses new leads.
Create private GitHub repository rgm-machinery-platform when an authorized authenticated account is available. Local files are not equivalent to a private remote backup. Never commit .env.local or credentials.
